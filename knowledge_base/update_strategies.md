一、总则
1.1 评估目标
对 GUI Agent 模型在移动端 APP 场景中的任务执行结果进行标准化评判，明确 完美执行 / 基本完成 / 失败 / 不计入 四级判定标准。
1.2 基础准则
核心原则：只要运行结果在逻辑上能够自圆其说、理由充分，且不与任务定义冲突，即使不是最优路径或最优结果，也视为任务完成。
- 以最终任务状态为判定依据，不以执行路径最优性为标准。
- 执行过程中的纠错、回退、冗余步骤，不直接否定正确性。
- 任务在前序步骤中已完成，后续多执行了若干无状态变更的步骤，仍视为完成。

三、成功判定规则（完美执行 & 基本完成）
3.1 任务完成性判定
R-S1：任务最终完成即判定成功
- 路径无关性：不要求最短执行路径；中间存在探索、纠错、回退均不影响判定。
- 多余步骤容忍：任务已完成后，若模型又执行了若干步骤但未改变任务状态，仍判定为成功。
- 典型场景：查看收货地址 —— 已到达地址页面后又点击了其他区域再返回，仍判定正确。
R-S2：多入口等价命中
- APP 中存在多个可满足任务要求的功能入口时，命中任意一个即可。
- 典型场景：「淘宝签到领金币」—— 从「天天签到」入口完成，与从「我的淘宝」入口完成，均视为正确。

3.2 合理接管判定
R-S7：正确触发求助接管
模型在以下场景中请求用户接管，视为正确行为，但最终状态需按三分法判断：
1. 历史步骤正确，接管时机正确，接管类型正确，take_over/terminate 总结正确，且已经非常接近目标完成页或最后人工确认边界，只剩用户确认、隐私输入、授权提交、支付确认等非环境类人工动作 → 基本完成。
2. 登录、实名、人机验证、账号激活、黑屏、目标应用未安装/启动失败、系统异常等客观阻断导致任务无法继续，且不是模型路径错误、探索不足或过早接管导致 → 不计入/环境错误；不得因接管时机或类型正确改判基本完成。
3. 历史路径错误、离目标页很远、无需接管、接管类型或总结错误、未充分探索、未按用户接续继续 → 失败。
a) 常识性不可执行
- 任务在目标 APP 中不存在对应功能（如：微信中浇树、QQ音乐中贷款）。
- 模型应在接管提示中明确说明不可执行的原因。
b) 明确的操作障碍
- 页面出现明确阻断提示：无VIP权限、未同意协议、搜索无结果、规格不存在、数量超限等。
- 典型场景：「搜索联系人张三」—— 无此联系人 → 请求接管并说明原因。
R-S8：接管优先级规则
当同时触发多个接管等级时：
- 0级（安全/隐私） 优先于 1级（信息缺失）。 
  - 例：「修改密码」同时涉及密码输入（0级）和信息缺失（1级），按0级处理。
- 同级别存在多个并列接管理由时，命中任一即可（言之有理）。

五、失败判定规则
5.1 执行卡死 / 无效循环
R-F1：页面卡死无响应
执行界面卡死在固定页面，所有操作均无响应。
暂时无法在HONOR E Link文档外展示此内容
- 典型场景：「在番茄免费小说中将某书加入书架」—— 页面不支持当前操作，模型反复点击 → 失败。
R-F2：死循环
模型陷入重复无效操作，无法跳出。
- 典型场景：「在快手极速版打开磁力金牛查看详情」—— 反复执行同一无效操作 → 失败。
5.2 关键约束违反
R-F3：关键约束缺失未询问
任务存在影响最终结果的关键性约束（列车时间、价格区间、出发地/目的地、距离排序等），真实场景中不存在满足该约束的目标时：
- 模型应先询问用户是否需要绕过部分约束。
- 未询问直接执行或继续盲目尝试 → 失败。
- 典型场景：「购买11月24日16:30南京到含山县汽车票」—— 无对应班次，模型未询问用户直接选择其他班次 → 失败。
R-F4：存在符合约束的目标但未命中
任务存在特殊且影响结果的约束，且实际存在满足条件的目标，但模型未选择该目标。
- 典型场景：「选择距离最近的泸溪河店铺」—— 未选距离最近的 → 失败。
5.3 任务状态被破坏
R-F5：任务完成后改变状态
执行轨迹中任务已完成，但模型未识别完成状态，继续操作并改变了任务状态。
- 任务已完成但模型进入无关页面或触发无关功能 → 失败。
- 典型场景：「在淘宝秒杀中砸金蛋」—— 已砸完金蛋但模型继续操作，进入其他页面 → 失败。
R-F6：未识别任务完成
任务实际已完成，但模型未推理出完成状态，继续执行不必要操作。
- 与 R-F5 的区别：即使后续未改变状态，未输出完成判定本身即为错误（当后续行为进入无关功能时）。
5.4 接管缺失或错误
R-F7：应接管未接管
在满足接管条件的场景下，模型未请求接管而继续错误执行。
暂时无法在HONOR E Link文档外展示此内容
- 典型场景： 
  - 「在番茄图书中将地球仪加入购物车」—— 功能不存在，接管但未说明原因 → 失败。
  - 「统计拼多多全部订单中最贵商品并收藏」—— 无订单，模型未说明 → 失败。

七、判定决策流程图
任务执行完成？
├── 是 → 核心目标达成？
│   ├── 是 → 所有约束满足 & 无瑕疵？
│   │   ├── 是 → 【完美执行】
│   │   └── 否 → 仅存在弱约束丢失/格式偏差/欠执行/过执行？
│   │       ├── 是 → 【基本完成】
│   │       └── 否（关键约束违反/状态被改变）→ 【失败】
│   └── 否 → 【失败】
├── 否 → 模型请求接管？
│   ├── 是 → 是否为登录/实名/人机验证/账号激活/黑屏/未安装/系统异常等客观环境阻断且非模型错误导致？
│   │   ├── 是 → 【不计入/环境错误】
│   │   └── 否 → 历史路径正确、接管时机/类型/总结正确且离目标完成页很近，只剩非环境类人工动作？
│   │       ├── 是 → 【基本完成】
│   │       └── 否 → 【失败】
│   └── 否 → 系统/工程原因导致？
│       ├── 是 → 【不计入】
│       └── 否 → 卡死/死循环/未识别完成？
│           └── 【失败】
